# 07 — v2.2 修复与校准：从"证明观点"到"理解系统"

> 版本: v2.2 | 日期: 2026-07-04 | 基于AI专家评估和4,800次模拟分析

---

## 一、v2.2 的设计动机

### 1.1 v2.1 的核心问题

通过4,800次批量模拟和专家评估，v2.1暴露了四个关键缺陷：

| # | 问题 | 证据 | 影响 |
|---|------|------|------|
| 1 | **EWS信号失效** | B和C的EWS_K_i≈0.73但从不崩溃，A的EWS_K_i≈0.73却系统崩溃 | 无法区分"结构性高压"与"临界逼近" |
| 2 | **策略B"过于完美"** | B在全部场景100%存活，GDP是A的25-83倍，无内生的高提取代价 | 模型缺乏现实感，高提取的社会成本未被建模 |
| 3 | **三部门固化** | 工业与数字是分离实体，缺少"智能制造"等融合业态 | 低估了渐进式转型的潜力 |
| 4 | **无政治经济学反馈** | 策略选择完全外生，不随社会支持度等状态调整 | 无法产生"政策被迫转向"等现实模式 |

### 1.2 v2.2 的设计哲学

> 从 **证明一个观点**（保守策略悖论）转向 **理解一个复杂系统**（多种崩溃/存活路径的条件和机制）。

v2.2的核心目标是让模型更**可信**、更**微妙**：
- 策略B不再"无敌"——它可能因为社会成本积累而被迫转向或崩溃
- 策略A不再"等死"——它可能通过升级存量工业资产实现转型
- EWS信号不再是"狼来了"——韧性指数区分真正的危险和系统特征

## 二、四大核心升级

### 2.1 EWS韧性指数

**问题**：EWS_K_i>0.7对B和C是常态（结构性特征），对A是终局预警。相同的阈值无法区分。

**方案**：引入**韧性指数 (Resilience Index)**，综合三个维度：

```
韧性指数 = 0.40 × 恢复速度 + 0.30 × 抗扰动幅度 + 0.30 × (1 - 压力持续性惩罚)
```

- **恢复速度**：变量从近期低谷回升的速率。高韧性系统即使受到冲击也能快速回弹。
- **抗扰动幅度**：变量曾经历的最大扰动程度。经历过重大冲击但未崩溃=高韧性。
- **压力持续性**：EWS连续处于高位的时间。持续性越长，越可能是结构性特征而非临界临近。

**动态状态判定**：
- 高韧性(>0.6)：阈值上调0.1——"结构性高压"只报warning
- 中等韧性(0.3-0.6)：按原阈值
- 低韧性(<0.3)：阈值下调0.1——更早预警

**代码实现**：`src/monitors/ews.py` 中的 `_compute_resilience()`, `_dynamic_status()`, `_estimate_recovery_speed()`

### 2.2 策略B的内生社会经济成本

**问题**：策略B的高提取率(30-60%)在现实中会产生严重的社会经济后果，但v2.1中完全缺失。

**方案**：三个渠道的内生成本：

#### 渠道1：就业破坏
当提取率超过30%时，每超出10个百分点，工业部门的正常就业流失加速15%。数字部门只能吸收部分流失的劳动力（技能不匹配），其余成为失业者。

```
额外失业 = L_i × (τ - 0.30) × 0.05 × dt
可吸收量 = L_d × DL_d × 0.02 × dt
净失业 = max(0, 额外失业 - 可吸收量)
```

#### 渠道2：消费萎缩
高提取 → 居民可支配收入占比下降 → 国内总需求减少 → 工业产出受需求侧约束。

```
可支配份额 = max(0.3, 0.7 - τ × 0.5)
消费拖累 = (0.70 - 可支配份额) × 0.15
```

#### 渠道3：资产泡沫/不平等
数字部门超额利润率(r_d > 25%) → 财富集中 → 代价基尼恶化 → 为社会崩溃提供渐进路径。

**代码实现**：`src/models/accumulation.py` 中的 `LeapAccumulation._apply_socioeconomic_costs()`

### 2.3 融合型工业：数字密度属性

**问题**：v2.1中工业与数字部门是分离实体。现实中，智能制造、产业互联网让"工业资本"和"数字资本"的边界日益模糊。

**方案**：在`SectorState`中新增`digital_density`属性：
- 定义：工业资本存量中嵌入数字技术的比例 [0, 1]
- 增长：每单位投资中，数字技术服务/软件/智能设备的比例取决于部门数字化水平
- 折旧：随资本折旧而流失（数字设备也有使用寿命）

**数字密度影响**：
1. **生产效率**：`density_gain = 1.0 + digital_density × 0.5`
2. **技术扩散**：`density_bonus = 1.0 + digital_density × 0.8`
3. **知识吸收准备度**：`dd_factor = 0.5 + 0.5 × digital_density`

**核心逻辑**：策略A可以通过提升工业部门的数字密度来实现"质变"，而不是单纯地"保护落后"。这使策略A的转型路径从"等死"变为"有条件地升级"。

**代码实现**：
- `src/core/state.py`：`SectorState.digital_density`
- `src/models/accumulation.py`：`_apply_investment()` 中数字密度动态
- `src/models/sectors.py`：`_industry_production()` 中 density_gain
- `src/models/technology.py`：`_diffuse_technology()` 中 density_bonus
- `src/models/technology_diffusion.py`：`_absorption_readiness()` 中 dd_factor

### 2.4 政治经济学反馈环

**问题**：v2.1中策略选择是完全外生的，不能在模拟过程中根据系统状态变化调整。现实中的政策会因社会压力而转向。

**方案**：新增`PoliticalEconomyModule`模块：

#### 政权支持度的四个分量

| 分量 | 权重 | 主要驱动因素 |
|------|------|-------------|
| 就业满意度 | 0.35 | 总就业率 + 工业就业占比 |
| 工资满意度 | 0.25 | 工业工资相对数字部门工资 + 失业者补偿 |
| 不平等容忍度 | 0.20 | 代价基尼系数 |
| 福利满意度 | 0.20 | 总体福利指数 |

#### 政策约束机制

- 支持度 > 0.6：约束乘数 = 1.0（策略空间完整）
- 支持度 0.4-0.6：线性下降至 0.7
- 支持度 0.2-0.4：加速下降至 0.35
- 支持度 < 0.2：严厉约束至 0.20

约束收紧快（惯性0.80），放松慢（惯性0.95）——反映了"政策收紧容易，放松难"的政治现实。

#### 抗议风险

```
抗议风险 = 0.35 × 支持度下降速度 + 0.30 × 代价集中度 + 0.25 × 失业风险 + 0.10 × 绝对支持度水平
```

当抗议风险 > 0.6 且支持度 < 0.35 时，触发"软化"信号——强制降低提取率、增加福利投资。

#### "先跳后崩"模式

这是v2.2的核心新叙事：

1. 策略B初期：高提取 → 数字部门快速增长 → GDP飙升
2. 社会压力积累：消费萎缩 + 工业失业 → 政治支持度持续下降
3. 政策被迫转向：支持度跌破0.25 → 提取率被强制压缩 → 数字投资断流
4. 双重打击：数字失去投资 + 工业失去反哺 → 系统崩溃

**代码实现**：
- 新建 `src/models/political_economy.py`：完整政治经济学模块
- `src/core/state.py`：`PoliticalSupport` 数据类
- `src/core/engine.py`：主循环中集成政治反馈 + 紧急政策调整
- `src/core/config.py`：新增 `political_feedback_enabled`, `political_update_interval`

## 五、预期效果变化

基于AI专家评估和理论分析，v2.2应产生以下变化：

1. **策略A的存活率可能上升**：数字密度属性允许工业通过渐进升级来追赶，不再"等死"
2. **策略B可能出现崩溃**：高提取率的社会成本积累可能引发"先跳后崩"模式
3. **策略C的优越性可能显现**：代价最均匀的特点使其政治支持度保持高位，政策空间更稳定
4. **EWS信号更有区分力**：韧性指数能区分B的"结构性高压"与A的"临界逼近"
5. **策略B的GDP优势可能缩小**：消费萎缩和就业破坏部分抵消了数字反哺的正面效果
