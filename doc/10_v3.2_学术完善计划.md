#### Q1/Q11/Q12：可证伪性 + 确认偏误 + 叙事vs计算

**问题本质**：模型是否只是把设计者已知的信念用代码复现了一遍？

**当前风险**：
- 策略命门的定义逻辑 = 断裂检测的触发逻辑（如"撕裂陷阱触发=代价比>2.5"）
- 所有断裂都可归类到预定义的九种模式
- 设计文档对模型结果的预期（如"B应该有先跳后崩模式"）与模型实际输出一致

**修复方案**：

| 行动 | 说明 |
|------|------|
| **运行"零假设基线"** | 设置所有策略参数相同（τ相同、φ相同），验证模型是否产出相同结果。如果不同，说明策略无关——这是最基础的检查 |
| **记录"意外发现"** | 在批量实验报告中专门增加一节："与设计预期不符的结果" |
| **独立断裂检测** | 写一个通用断裂检测器——不基于预定义的断裂名称，而是基于状态变量的突变检测（ΔX/Δt > 3σ 的历史波动），然后看通用检测器找到的断裂是否都能被预定义的九种模式覆盖 |
| **声明"定义性断裂"与"涌现性断裂"的区别** | 在论文中明确说明：哪些断裂是预定义的（=理论推导），哪些是涌现的（=模拟发现）。如果所有断裂都是预定义的，诚实地说明这一点 |

**代码检查点**：
```python
# 1. 零假设基线测试
def test_null_hypothesis():
    """当三种策略参数完全相同时，输出应无统计差异"""
    for regime in ['A', 'B', 'C']:
        params = make_identical_params(regime)  # 所有策略参数强制相同
        result = run(params)
    # 验证：CDI差异 < 0.05

# 2. 通用断裂检测器
def detect_anomalies_generic(ts: np.ndarray, window: int = 20) -> list:
    """不基于预定义阈值的通用异常检测"""
    rolling_mean = np.convolve(ts, np.ones(window)/window, mode='valid')
    rolling_std = np.convolve(np.abs(np.diff(ts)), np.ones(window-1)/(window-1), mode='valid')
    anomalies = []
    for i in range(1, len(ts)):
        if abs(ts[i] - rolling_mean[min(i, len(rolling_mean)-1)]) > 3 * rolling_std[min(i-1, len(rolling_std)-1)]:
            anomalies.append(i)
    return anomalies
```

#### Q4：SFC残差监控

**问题本质**：SFC闭合通过"未计划库存变化"吸收残差——如果残差在压力时刻系统性膨胀，那模型在靠"会计魔术"抑制断裂。

**修复方案**：

| 行动 | 说明 |
|------|------|
| **持续监控残差** | 在 recorder 中新增 `sfc_residual_ratio` 变量：残差 / 总交易量 |
| **设置残差告警** | 当残差比超过5%时，记录 WARNING；超过10%时，该模拟标记为"SFC可信度低" |
| **在论文中报告** | 报告所有模拟的残差分布：中位数、95分位数、最大值，以及在断裂前后的变化 |

**代码检查点**：
```python
# 在 SFCClosure.check_and_close() 中增加
residual_ratio = abs(residual) / max(total_transactions, 1.0)
state.sfc_residual_ratio = residual_ratio
if residual_ratio > 0.10:
    state.sfc_trustworthiness = "LOW"
```

#### Q2：参数敏感性

**问题本质**：108个参数，核心结论对非核心参数的敏感度未知。

**修复方案**：

| 行动 | 说明 |
|------|------|
| **关键发现的逐个参数扰动** | 对论文中报告的核心发现（如"资源富国选A触发红线"），逐个扰动所有L1结构参数±20%，检验结论是否翻转 |
| **Sobol敏感性（聚焦版）** | 不跑全部108个参数的Sobol（计算量过大），而是在"最有趣的参数区域"对10-15个最敏感参数做Sobol |
| **报告"稳健性评分"** | 对每个核心发现，报告它对其最敏感参数的弹性——弹性>1的发现需要谨慎表述 |

**问题本质**：红线阈值是规范性选择，但如果结论对阈值高度敏感，规范就不具备说服力。

#### Q14：从未触发的断裂

**问题本质**：如果某种断裂从未被触发，是机制排除了它，还是它确实不可能？

**修复方案**：

| 行动 | 说明 |
|------|------|
| **编制断裂触发矩阵** | 对九种断裂模式 × 六种国情 × 八种场景 × 三种策略，统计每种断裂的触发频率 |

#### Q5：劳动力流动的选择效应

**问题本质**：当前劳动力流动是总量层面（N个从I到D），但实际是分层筛选——高技能先走，留下低技能。

**修复方案**：

| 行动 | 说明 |
|------|------|
| **增加"技能分层流动"** | 当数字部门扩张时，工业部门流出的劳动力中，技能匹配度高的优先转移 |
| **追踪"留守者质量"** | 新增指标：`industrial_skill_erosion` = 当前工业劳动者平均技能 / 初始工业劳动者平均技能 |
| **策略B的人力资本破坏渠道** | 这个机制会显著改变策略B的评价——人均GDP可能仍然高（数字部门生产率高），但工业留守者的福利恶化被单独暴露 |

**代码修改**：`labor_market.py` 中，劳动力流动从 `dL = f(w_diff)` 改为 `dL_high_skill = f(w_diff, skill_match) * H_i_share`，`dL_low_skill = residual`。

#### Q6：反哺执行的政治经济学

**问题本质**：反哺成功概率当前只取决于制度能力+利润率，但缺少数字部门**主动抵制反哺**的行为模型。

**修复方案**：

| 行动 | 说明 |
|------|------|
| **增加"反哺抵制指数"** | `feedback_resistance = f(r_d, political_power_of_digital_sector, 制度能力)` |
| **反哺执行力度受抵制调节** | 即使"触发"了反哺，实际执行比例 = 名义反哺比例 × (1 - 抵制指数) |
| **极端情况** | 当数字部门占GDP>60%且利润率>30%时，反哺可能名义上触发但实际上被截留80% |

**代码修改**：`accumulation.py` 中的 `LeapAccumulation._feedback_success_probability()` 增加抵制维度。

#### L9/Q9：混合策略组合效应 + 五维相关性

**问题本质**：(1) 混合策略的线性加权可能低估协同/拮抗效应；(2) 五维评价的独立性需要被验证。

**修复方案**：

| 行动 | 说明 |
|------|------|
| **增加策略交互项** | τ_effective = λ_A·τ_A + λ_B·τ_B + **γ_AB·λ_A·λ_B**（交叉效应参数） |
| **生成五维相关性矩阵** | 在批量实验报告中输出五个维度间的 Pearson/Spearman 相关系数矩阵 |
| **识别"张力的维度"** | 如果民生福祉和经济增长在某些条件下负相关，这本身就是最重要的发现 |

## 四、论文中的"自觉性声明"清单

以下声明应在论文的方法论部分或结论部分出现：

1. **可证伪性声明**："本模型不声称预测特定国家的结果。它的可证伪性体现在：明确的参数组合应产生明确的结果模式，如果历史案例的系统性模式与模型预测矛盾，则构成对模型机制的反驳。"

2. **确认偏误防护**："我们区分了'定义性断裂'（从理论推导的阈值条件）和'涌现性发现'（模拟中未预期出现的模式）。在附录中报告了通用异常检测器的结果，以证明模型产生的动态不限于预定义的分类。"

3. **参数敏感性声明**："对论文中报告的每项核心发现，我们进行了逐个参数的±20%扰动检验。发现[X]对参数[Y]的敏感度最高（弹性=[Z]），但结论在合理范围内保持稳健。"

4. **SFC可信度声明**："所有模拟中，SFC会计闭合残差占总交易量的中位数为[X]%，最大值为[Y]%。在断裂临界点附近，残差比[上升/稳定]，表明核算框架[在压力下保持可信/在极端条件下可信度下降]。"

5. **红线敏感性声明**："人道主义红线的阈值进行了±25%的敏感性分析。核心发现——[如'资源富国选A不可接受']——在阈值变化范围内[保持/变化]。"

6. **已知盲区声明**："模型当前不包含服务业独立部门、金融部门行为、气候反馈、非正式经济等维度。这些盲区意味着模型在以下方面可能产生偏差：低估服务业的就业吸收能力、高估信贷可得性、忽略绿色转型的外部压力。"

## 五、总结：v3.2 的目标

v3.2 不是一个"增加新功能"的版本——它是为论文答辩做准备的**防御性加固**。核心目标：

1. **让模型可以被质疑**——通过零假设测试、通用断裂检测、敏感性分析、残差监控
2. **让结论具有稳健性**——展示核心发现在参数扰动和阈值变化下的稳定性
3. **让盲区被诚实标记**——不假装模型覆盖了它没覆盖的东西
4. **让方法论自觉可见**——审查者能看到你思考过这些问题

这比增加任何新功能都更重要。
