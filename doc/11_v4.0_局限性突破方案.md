## 方案一：平台垄断与"赢家通吃"结构（P0）

### 为什么这是最重要的缺失

当前 d_app 生产函数中，网络效应（`eta_network_app`）只是一个温和的产出增益因子。这严重低估了数字经济的核心特征：**平台具有自然垄断属性，第一名拿走大部分利润，第二名勉强存活，第三名及以后不存在。** 这意味着：

- 数字部门的增长收益不是均匀分配的——winner-takes-all
- 垄断平台可能演变为政治垄断（数据+算法+舆论）
- 垄断租金抑制创新（收购潜在竞争者而非与之竞争）
- 但垄断也带来效率——统一标准、网络效应最大化

### 设计方案

#### 新增状态变量

```python
@dataclass
class PlatformStructure:
    """d_app 部门内部的平台市场结构."""
    
    # 市场集中度
    hhi_index: float = 0.25          # Herfindahl-Hirschman指数 [0,1], 1=完全垄断
    top1_share: float = 0.40         # 第一名市场份额
    top3_share: float = 0.70         # 前三名市场份额
    
    # 垄断行为
    monopoly_rent_ratio: float = 0.0  # 垄断租金占利润比例
    acquisition_rate: float = 0.0     # 并购潜在竞争者的速率（年化）
    entry_barrier: float = 0.3        # 新进入者的门槛高度 [0,1]
    
    # 政治维度
    platform_political_spend: float = 0.0  # 平台政治游说支出/GDP
    data_monopoly_power: float = 0.0       # 数据垄断带来的额外政治影响力
```

#### 核心机制

**机制1：网络效应 → 自然集中**

```python
def _update_platform_structure(state, dt):
    """平台市场结构演化."""
    ps = state.platform_structure
    
    # 网络效应越强 → 集中度自然上升
    net_effect = state.sectors["d_app"].DL * p["eta_network_app"]
    natural_concentration = net_effect * 0.15  # 每单位网络效应推高HHI 0.15
    
    # 规模经济 → 第一名份额扩大
    scale_advantage = (state.sectors["d_app"].K / max(state.sectors["d_app"].L, 0.01))
    top1_gain = 0.02 * (scale_advantage / 100) * dt
    
    # 更新
    ps.hhi_index += (natural_concentration - ps.hhi_index * 0.1) * dt
    ps.top1_share = min(0.95, ps.top1_share + top1_gain)
    ps.hhi_index = max(0.1, min(0.95, ps.hhi_index))
```

**机制2：垄断租金的双面效应**

垄断租金 = f(市场集中度, 反垄断政策力度)

正面：高利润 → 更多R&D投资 → 技术进步加速
负面：抑制竞争 → 长期创新动力下降 + 消费者福利损失 + 政治权力膨胀

```python
def _compute_monopoly_effects(state, dt):
    ps = state.platform_structure
    
    # 正面：垄断利润→研发投资
    rd_boost = ps.monopoly_rent_ratio * 0.3 * state.sectors["d_app"].profit
    state.sectors["d_app"].A *= (1.0 + rd_boost / max(state.sectors["d_app"].K, 0.01) * 0.1 * dt)
    
    # 负面1：长期创新抑制（3-5年后显现）
    if ps.top1_share > 0.7:
        innovation_drag = (ps.top1_share - 0.7) * 0.02 * dt
        # 延迟效应通过队列管道实现——今天的垄断损害5年后的创新
        state.sectors["d_app"].A *= (1.0 - innovation_drag * 0.5)  # 短期影响小
    
    # 负面2：垄断租金→政治权力
    ps.platform_political_spend = ps.monopoly_rent_ratio * state.sectors["d_app"].profit * 0.05
    state.households.digital_high_skill.political_power = min(0.50, 
        0.30 + ps.platform_political_spend / max(state.gdp, 0.01) * 2.0)
```

**机制3：反垄断政策**

```python
# 新增参数
p["antitrust_intensity"] = 0.2     # 反垄断执法力度 [0, 1]
p["antitrust_threshold"] = 0.5     # 触发反垄断的HHI阈值
p["data_portability"] = 0.1        # 数据可携带性 [0, 1]——降低切换成本
p["interoperability_mandate"] = 0.0 # 互操作性强制要求 [0, 1]

def _apply_antitrust(state, dt):
    ps = state.platform_structure
    anti = p["antitrust_intensity"]
    
    if ps.hhi_index > p["antitrust_threshold"]:
        # 反垄断介入：拆分威胁 → 集中度下降
        breakup_pressure = (ps.hhi_index - p["antitrust_threshold"]) * anti * 0.1 * dt
        ps.hhi_index -= breakup_pressure
        ps.top1_share -= breakup_pressure * 0.5
        
        # 数据可携带性 → 降低进入壁垒
        ps.entry_barrier *= (1.0 - p["data_portability"] * 0.3 * dt)
```

#### 新增参数（6个）

| 参数 | 符号 | 范围 | 默认 | 说明 |
|------|------|------|------|------|
| antitrust_intensity | α_anti | [0, 1] | 0.2 | 反垄断执法力度 |
| antitrust_threshold | HHI_th | [0.3, 0.8] | 0.5 | 触发反垄断的HHI |
| data_portability | δ_port | [0, 1] | 0.1 | 数据可携带性 |
| interoperability_mandate | ι_interop | [0, 1] | 0.0 | 互操作性强制 |
| monopoly_innovation_boost | μ_innov | [0.1, 0.5] | 0.3 | 垄断利润→研发转化率 |
| monopoly_innovation_decay | μ_decay | [0.01, 0.05] | 0.02 | 垄断长期创新衰减率 |

#### 理论收益

- **直接检验**：平台垄断是否必然导致"创新停滞"（Schumpeter vs Arrow 争论的可计算版本）
- **政策实验**：不同反垄断力度下的数字经济发展路径——欧盟模式 vs 美国模式 vs 中国模式
- **政治经济学**：平台的政治权力是否从经济垄断中自然生长出来？
- **与现有断裂联动**：新增第13种断裂——"平台俘获国家"(platform_state_capture: top1_share>0.8 + political_power>0.45)

## 方案二：空间/区域维度（P1）

### 为什么重要

当前模型是完全聚合的——数字部门在哪里发展、工业在哪里萎缩，没有空间坐标。这意味着无法回答：

- 沿海数字繁荣+内陆工业衰退是否加剧政治分裂？
- 劳动力跨区域流动的摩擦是否延缓了结构调整？
- 区域间财政转移支付是否能够缓和空间不平等？

### 设计方案：简化的双区域模型

不是全面空间一般均衡，而是**双区域二分法**——将六部门分布到两个区域：

```
区域C (Coastal/Urban):    区域I (Inland/Rural):
  d_infra: 80%               d_infra: 20%
  d_app:   90%               d_app:   10%
  s_high:  75%               s_high:  25%
  i:       55%               i:       45%
  s_low:   50%               s_low:   50%
  b:       20%               b:       80%
```

#### 新增状态

```python
@dataclass
class RegionalDistribution:
    """六部门在两区域的分布."""
    # 每个部门的区域C份额 [0,1], 区域I = 1 - share
    shares: Dict[str, float]   # {"d_infra": 0.8, "d_app": 0.9, ...}
    
    # 区域间工资比
    wage_ratio_ci: float = 2.0   # W_coastal / W_inland
    
    # 劳动力迁移
    migration_flow: float = 0.0  # I→C 年迁移量（万人）
    migration_cost: float = 0.5  # 迁移成本（年收入倍数）
    
    # 区域不平等
    regional_gini: float = 0.0
    fiscal_transfer: float = 0.0  # C→I 财政转移/GDP
```

#### 新增参数（5个）

| 参数 | 默认 | 说明 |
|------|------|------|
| migration_friction | 0.5 | 迁移摩擦系数 |
| regional_spillover | 0.15 | C→I 技术溢出强度 |
| fiscal_transfer_rate | 0.05 | 区域转移支付力度 |
| coastal_agglomeration | 0.02 | 沿海集聚经济效应 |
| inland_cost_advantage | 0.3 | 内陆成本优势（低工资+低地价）|

#### 核心动态

```python
def _update_regional_dynamics(state, dt):
    reg = state.regional
    
    # 工资差距驱动迁移
    wage_gap = reg.wage_ratio_ci - 1.0
    migration_pressure = wage_gap * 0.1 * (1 - p["migration_friction"])
    reg.migration_flow = state.households.total_population * migration_pressure * dt
    
    # 集聚效应：数字部门在区域C的集中度自我强化
    for key in ["d_infra", "d_app", "s_high"]:
        agglomeration = p["coastal_agglomeration"] * reg.shares[key] * dt
        reg.shares[key] = min(0.95, reg.shares[key] + agglomeration)
    
    # 技术溢出：区域C的知识向区域I扩散
    spillover = p["regional_spillover"] * (1 - reg.shares["i"]) * dt
    # 区域I的工业技术水平受益于沿海的技术溢出
    
    # 财政转移：缓和区域不平等
    reg.fiscal_transfer = p["fiscal_transfer_rate"] * (reg.wage_ratio_ci - 1.0)
    reg.regional_gini = compute_regional_gini(state, reg)
```

#### 理论收益

- **区域不平等** vs **国家整体增长**：某些策略可能提升全国GDP但加剧区域撕裂
- **迁移壁垒**：如果劳动力无法自由流动，去工业化地区的痛苦被放大
- **财政联邦主义**：转移支付能否在"效率"和"公平"之间找到平衡？

## 方案三：官僚集团内部博弈（P2）

### 为什么重要

当前模型中国家是统一理性行动者——策略一旦选定就不变（除了政治支持度崩溃时的紧急调整）。但现实中：

- 工业官僚 vs 数字经济官僚存在持续的预算争夺
- 地方官员的晋升激励可能与国家整体策略冲突
- 腐败截留投资——实际到达部门的投资小于计划投资

### 设计方案：简化的双官僚模型

```python
@dataclass
class BureaucraticFactions:
    """国家内部的两大官僚集团."""
    
    # 工业官僚（传统发展型国家遗产）
    industrial_faction_power: float = 0.55  # 政治影响力份额
    industrial_faction_cohesion: float = 0.7 # 内部凝聚力
    
    # 数字官僚（新兴数字经济利益）
    digital_faction_power: float = 0.45
    digital_faction_cohesion: float = 0.6
    
    # 博弈结果
    budget_allocation_bias: float = 0.0    # >0偏向数字, <0偏向工业
    policy_delay: float = 0.0             # 内部扯皮导致的政策延迟（年）
    corruption_leakage: float = 0.05      # 腐败截留占投资比例
```

#### 核心机制

```python
def _update_bureaucratic_game(state, dt):
    bf = state.bureaucratic
    
    # 部门增长 → 对应官僚集团权力增强
    industrial_growth = state.sectors["i"].Y / max(prev_i_Y, 0.01) - 1
    digital_growth = (state.sectors["d_infra"].Y + state.sectors["d_app"].Y) / max(prev_d_Y, 0.01) - 1
    
    # 权力转移：哪个部门增长快，对应官僚集团权力上升
    power_shift = (digital_growth - industrial_growth) * 0.1 * dt
    bf.digital_faction_power = max(0.2, min(0.8, bf.digital_faction_power + power_shift))
    bf.industrial_faction_power = 1.0 - bf.digital_faction_power
    
    # 预算偏差 = 权力差距
    bf.budget_allocation_bias = (bf.digital_faction_power - 0.5) * 0.3
    
    # 内耗 → 政策延迟
    power_gap = abs(bf.digital_faction_power - bf.industrial_faction_power)
    if power_gap < 0.1:
        # 势均力敌 → 僵局 → 政策延迟最大
        bf.policy_delay = 2.0  # 2年
    else:
        bf.policy_delay = 0.5
    
    # 腐败：制度能力弱 → 漏损高
    bf.corruption_leakage = max(0.01, 0.10 - p["institution_capacity"] * 0.08)
```

#### 新增参数（4个）

| 参数 | 默认 | 说明 |
|------|------|------|
| initial_industrial_power | 0.55 | 初始工业官僚权力份额 |
| faction_adaptation_speed | 0.1 | 权力随部门表现变化的速度 |
| deadlock_penalty | 2.0 | 僵局时的政策延迟（年）|
| corruption_base_rate | 0.05 | 基准腐败漏损率 |

#### 理论收益

- **发展型国家理论**：为什么韩国/日本的工业官僚能够有效执行产业政策，而其他国家的类似尝试沦为寻租？
- **官僚俘获**：数字经济崛起是否必然导致工业官僚的衰落？这对产业政策的连续性意味着什么？
- **"反腐"作为自变量**：制度能力提升→腐败漏损降低→投资效率提升——这个因果链条是否足够强？

## 方案四：内生人口动态（P1）

### 为什么重要

当前人口是固定的。但100年时间尺度上：

- 高收入群组生育率下降 → 数字精英人口萎缩
- 老龄化 → 养老金压力上升 → 挤占产业投资
- 劳动力供给收缩 → 工业部门的低成本优势消失
- 教育投资的代际效应需要内生人口来承载

### 设计方案：简化的群组生育率模型

```python
@dataclass
class DemographicState:
    """人口动态状态."""
    
    # 各群组生育率（每个女性终身生育数）
    fertility_rates: Dict[str, float]  # 按群组
    
    # 各群组死亡率
    mortality_rates: Dict[str, float]
    
    # 年龄结构（简化：分为 0-20/20-65/65+ 三组）
    youth_share: float = 0.30
    working_age_share: float = 0.60
    elderly_share: float = 0.10
    
    # 代际流动
    intergenerational_mobility: float = 0.3  # 底层→高技能的概率
    
    # 老龄压力
    dependency_ratio: float = 0.17  # (youth + elderly) / working_age
    pension_pressure: float = 0.0   # 养老金支出/GDP
```

#### 核心机制

```python
def _update_demographics(state, dt):
    dem = state.demographics
    
    # 群组差异化生育率：收入越高 → 生育率越低
    base_fertility = {
        "digital": 1.2,     # 数字精英最低
        "industrial": 1.6,  # 工业工人中等
        "service": 1.8,     # 服务业偏高
        "base": 2.5,        # 基础部门最高
        "unemployed": 2.0,
    }
    
    # 生育率还受教育水平影响（人力资本越高→越低）
    for group_name, hh in [
        ("digital", state.households.digital_high_skill),
        ("industrial", state.households.industrial_workers),
        ("service", state.households.service_workers),
        ("base", state.households.base_workers),
    ]:
        education_effect = max(0.5, 1.0 - (hh.skill_level - 0.5) * 0.5)
        dem.fertility_rates[group_name] = base_fertility[group_name] * education_effect
    
    # 人口自然增长
    for group_name, hh in state.households.all_groups():
        births = hh.population * dem.fertility_rates.get(group_name, 1.5) * 0.02 * dt  # 年化
        deaths = hh.population * dem.mortality_rates.get(group_name, 0.01) * dt
        hh.population += (births - deaths)
        hh.population = max(0.1, hh.population)
    
    # 老龄化 → 养老金压力
    dem.elderly_share += 0.001 * dt  # 年增0.1%（简化）
    dem.dependency_ratio = (dem.youth_share + dem.elderly_share) / max(dem.working_age_share, 0.01)
    dem.pension_pressure = dem.elderly_share * 0.15  # 老年人均消耗15%GDP
```

#### 新增参数（5个）

| 参数 | 默认 | 说明 |
|------|------|------|
| base_fertility_digital | 1.2 | 数字群组基准生育率 |
| base_fertility_industrial | 1.6 | 工业群组基准生育率 |
| base_fertility_base | 2.5 | 基础部门基准生育率 |
| education_fertility_elasticity | 0.5 | 教育对生育率的抑制弹性 |
| intergenerational_mobility_rate | 0.3 | 代际流动概率 |

## 方案五：参数校准框架（P0）

### 为什么重要

当前~120个参数中，大部分默认值来自理论推断而非经验校准。这限制了模型的定量可信度。但我们不需要（也不可能）精确校准所有参数——关键是：

1. 识别哪些参数对结论最关键（敏感性分析）
2. 对这些关键参数进行经验校准
3. 对其余参数进行合理的稳健性区间设定

### 设计方案：三层校准框架

#### 第一层：关键参数识别

利用已有的Sobol敏感性分析（`13_sobol_sensitivity.py`），识别对CDI和断裂触发影响最大的top-20参数。这些是关键校准对象。

#### 第二层：经验校准（针对3个参照国）

选择3个参照国，对其历史轨迹进行简化校准：

| 参照国 | 对应国情预设 | 校准时期 | 校准目标 |
|--------|------------|---------|---------|
| 韩国 | manufacturing_giant | 1980-2020 | 工业→数字转型路径 |
| 印度 | digital_leapfrogger | 2000-2020 | IT服务驱动的跳跃式发展 |
| 尼日利亚 | resource_rich | 2000-2020 | 资源依赖+荷兰病 |

校准方法：最小化模型输出与历史观测之间的加权距离

```python
def calibration_objective(params, target_country, target_period):
    """校准目标函数."""
    # 运行模型
    engine = SimulationEngine(params=params, country_profile=target_country, ...)
    result = engine.run()
    
    # 提取模型输出
    model_output = {
        "gdp_growth": extract_gdp_growth_trajectory(result),
        "industrial_share": extract_industrial_gdp_share(result),
        "tech_gap": result["summary"]["final_tech_gap"],
        "gini": result["summary"]["final_gini"],
        "digital_share": extract_digital_gdp_share(result),
    }
    
    # 与历史数据比较
    historical = load_historical_data(target_country, target_period)
    error = sum(
        weight_i * (model_output[k] - historical[k])**2
        for k, weight_i in CALIBRATION_WEIGHTS.items()
    )
    return error
```

#### 第三层：稳健性区间

对于非关键参数，不追求"精确值"，而是确定一个"合理区间"：

- 区间宽度 = f(参数敏感度) —— 越不敏感的参数，区间越宽
- 在区间内均匀采样 → 结论的分布而非点估计
- 如果结论在区间内稳健 → 即使参数不确定，定性发现仍然可靠
